# NeuroStars Games Tracker

Статический административный сайт для просмотра учеников, журнала занятий и результатов обучающих игр из Cloud Firestore.

Текущий этап включает сайт-трекер, админку, журнал занятий и отдельный версионированный модуль отправки игровых результатов.

## 1. Подключение Firebase

Откройте файл `js/firebase-config.js` и замените тестовый объект `firebaseConfig` на объект, полученный в Firebase Console:

1. Откройте Firebase Console.
2. Перейдите в **Project settings** → **General**.
3. Найдите раздел **Your apps** и зарегистрированное Web App.
4. Выберите **SDK setup and configuration** → **Config**.
5. Скопируйте только содержимое объекта `firebaseConfig`.
6. Вставьте значения в `js/firebase-config.js`.

Пароль администратора в файлы проекта добавлять нельзя. Его нужно вводить только в форме входа.

## 2. Локальный запуск

ES-модули нельзя надёжно проверять простым двойным кликом по `index.html`. Запустите локальный HTTP-сервер.

### Вариант с Python

Откройте PowerShell в папке проекта и выполните:

```powershell
python -m http.server 8000
```

Затем откройте:

`http://localhost:8000/`

Чтобы остановить сервер, вернитесь в PowerShell и нажмите `Ctrl+C`.

Если команда `python` не найдена, попробуйте:

```powershell
py -m http.server 8000
```

### Вариант с Visual Studio Code

Если Python не установлен, можно открыть папку проекта в Visual Studio Code, установить расширение **Live Server**, нажать правой кнопкой мыши на `index.html` и выбрать **Open with Live Server**. Браузер обычно откроет адрес вида `http://127.0.0.1:5500/`.

## 3. Что проверить

1. До заполнения `firebaseConfig` форма должна показать понятное предупреждение и не разрешать вход.
2. После заполнения конфигурации войдите с Email и паролем администратора.
3. На странице учеников должен появиться документ `students/s001`.
4. В общей сводке должна отображаться одна активная игра, если у `games/forest-trails` поле `active` не равно `false`.
5. Поиск должен находить ученика по имени и по `s001`.
6. Кнопка **Открыть** должна вести на историю ученика.
7. Пока Forest Trails не подключена, история может быть пустой — это нормальное состояние.
8. В фильтре игр должна присутствовать Forest Trails.
9. Кнопка **Выйти** должна завершить сеанс и вернуть на страницу входа.
10. После выхода прямое открытие `dashboard.html` должно снова перенаправить на вход.

### Проверка журнала занятий

Перед проверкой добавьте блок правил из `LESSON_RECORDS_RULES.md` в Firestore Rules и опубликуйте правила.

1. Откройте карточку существующего ученика.
2. Перейдите во вкладку **Занятия**.
3. Нажмите **+ Добавить занятие**.
4. Заполните дату и четыре основных блока, затем сохраните запись.
5. Проверьте, что запись появилась первой в истории этого ученика.
6. Откройте запись, отредактируйте её и сохраните повторно.
7. Проверьте удаление с подтверждением.
8. Убедитесь, что вкладка **Игры** по-прежнему показывает персональные ссылки и историю попыток.

### Проверка тестовой отправки

1. Выйдите из административного трекера или откройте тест в отдельной вкладке.
2. Откройте `http://localhost:8000/test-game-result.html?student=s001`.
3. Убедитесь, что на странице указаны `s001` и `forest-trails`.
4. Нажмите **Отправить тестовый результат** только один раз.
5. Дождитесь зелёного сообщения с ID созданного документа.
6. Не обновляйте страницу до проверки Firestore: обновление начинает новую тестовую попытку.
7. После проверки снова войдите в административный трекер и откройте историю `s001`.

Если Firestore возвращает `Missing or insufficient permissions`, проверьте, что ID документа `admins/{uid}` точно совпадает с UID вошедшего Email/Password-пользователя и правила разрешают этому администратору чтение `admins`, `students`, `games` и `gameResults`.

## 4. Структура

```text
index.html                 страница входа
dashboard.html             список учеников и сводка
student.html               обзор, занятия и игры выбранного ученика
css/styles.css             общие адаптивные стили
js/firebase-config.js      подключение Firebase
js/auth.js                 вход, выход и проверка admins/{uid}
js/firestore.js            чтение и запись данных Firestore
js/ui.js                   форматирование и общие UI-функции
js/login-page.js           логика страницы входа
js/dashboard-page.js       логика списка учеников
js/student-page.js         логика карточки ученика и журнала занятий
js/test-game-result-page.js логика тестовой отправки
shared/v1/game-reporter.js версионированный модуль отправки результата
test-game-result.html      служебная тестовая страница
IMPLEMENTATION_PLAN.md     утверждённый план проекта
LESSON_RECORDS_RULES.md    правила Firestore для журнала занятий
```
